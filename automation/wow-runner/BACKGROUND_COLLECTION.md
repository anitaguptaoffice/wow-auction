# 后台采集统一入口（实机验收中）

这条流程使用官方客户端、Go 只读状态检测和定向窗口消息。旧 `wow-runner -run` 仍是前台/OCR 版本，不要用它替代本入口。

构建：`go build -o wow-collector.exe ./cmd/state-probe`

运行：`wow-collector.exe -collect-config C:/absolute/path/collect.json`

```json
{
  "exe": "F:/World of Warcraft/_retail_/Wow.exe",
  "output": "C:/collection/new-run-directory",
  "scanTimeoutSeconds": 240,
  "noResponseSeconds": 60,
  "cooldownSeconds": 900,
  "maxCooldownRetries": 2,
  "cycleIntervalSeconds": 14400,
  "sync": {
    "enabled": true,
    "server": "https://wowplayer.fun",
    "tokenFile": "C:/private/wow-auction-sync.token",
    "queueDir": "C:/collection/sync-outbox"
  },
  "characters": [
    {
      "name": "角色名",
      "realm": "服务器",
      "source": "F:/World of Warcraft/_retail_/WTF/Account/账号/服务器/角色名/SavedVariables/AuctionSearchExample.lua"
    }
  ]
}
```

不设置 `cycleIntervalSeconds` 时按原单次采集运行；设置为 14400 时常驻，每轮启动时间间隔至少 4 小时。上一轮超过 4 小时时，等完成后才启动下一轮，绝不并行。每轮在 `output/cycle-时间戳/` 独立记录 `events.jsonl` 和归档；服务在 `output/schedule.json` 持久记录轮次、已完成角色数和下一轮时间。具名单例锁阻止同时启动多个采集控制器。

单次采集要求 `output` 不存在；循环模式首次运行创建它，之后只接受匹配配置的已有调度目录。服务重启后若上轮已完成，沿用保存的下一轮时间；若上轮失败或中断，先结束核对路径后的 WoW 进程，记录恢复状态并等待至少 15 分钟，再重新启动客户端。恢复时重新验证本轮每个归档的压缩包和快照 SHA、完整性、角色、服务器及时间；通过的跳过，其他角色使用新的尝试目录重跑，旧文件保留。进度数字只是显示信息，不是判断角色完成的依据。

强制结束进程会丢失尚未落盘的游戏内状态，但不会删除已归档文件。自动恢复依赖官方客户端当前可用的登录凭据：若凭据失效或需要人工验证，重启本身不能续期；程序会按冷却间隔继续尝试并记录失败，不能保证自动登录成功。

启用 `sync` 后，归档完成即写入持久队列，独立 Go 工作线程将 Lua 以两次流式读取转换为 `snapshot.jsonl.gz`，按时间顺序申请任务、上传并等待 `succeeded` 回执；不阻塞后续角色采集。令牌只从本地文件读取，不写入队列或日志。服务忙遵守 `Retry-After`；断网或重启后沿用原文件 SHA 和任务 ID；`publication_unknown` 只查询原任务，不重新提交。服务端明确失败三次或本地校验失败进入 `attention`，保留文件并暂停后续上传，以免漏掉旧快照。若 Lua 副本丢失，先校验并从压缩归档恢复；扫描周期目录时可补上崩溃前遗漏的入队。同步工作线程随常驻控制器运行，故自动同步只允许配置在循环模式。

接口、格式和队列的模拟测试已通过；真实遗忘海岸快照的 408,151 条记录与先前转换结果逐条一致。持久队列使用同一份已发布快照进行了线上回放，得到原成功回执、`added_scans: 0`；整个 11 角色循环和采集后新快照自动上传尚待实机验收。

待办：用户日常使用中观察到登录态通常长期有效，在其他设备登录或主动登出后才可能失效。当前先复用现有登录态，不把凭据续期作为采集流程的阻塞项；将来再处理凭据失效识别、重新认证和人工验证流程。该有效期是用户经验，尚未建立保证。

控制器异常退出而游戏里的扫描仍有效时，可在该角色条目填入 `resumeSession` 和 `resumeRun`（来自已核实的本次心跳）。二者必须同时提供并精确匹配新读取的状态；这会继续等待/归档原扫描，不重新扫描。会话已变化则拒绝续接。

## 状态与动作

1. 找到匹配完整路径的唯一 WoW 进程并复用。若队列角色的 `AddOns.txt` 禁用了 AuctionSearchExample，先发一次正常窗口关闭消息，确认进程退出，再备份并仅启用该插件；关闭失败则不写配置、不强杀。客户端不存在时执行一次 `Wow.exe -launcherlogin -uid wow`。也可用 `launchCommand` 字符串数组指定已有启动器的绝对路径和参数。该字段不得放票据/密码；本程序不提取凭据或自动续期。
2. 校验受支持的 EXE 构建，读取两次一致的原生角色列表。按角色名和服务器唯一匹配。逐键导航、逐次读回，不能把原生数组下标当作 UI 行号。仅在准确选中后发送 Enter。
3. 等待插件 `WAST1` 心跳的序号递增，核对角色/服务器。原生“非选角”标记不代表已经进入世界。
4. 已打开拍卖行则直接进入扫描等待。否则确认非战斗、无施法：未骑乘时输入 `/cast [nomounted,nocombat] 雄壮商队雷龙`；已有其他坐骑时停止。
5. 确认雷龙已激活后输入 `/targetexact 收集者温塔`，确认目标，再按用户已绑定的 F1。收到插件拍卖行打开状态才继续。
6. 插件自动采集必须开启。首次打开拍卖行，本次登录最多自动请求一次。60 秒没有快照时标为“疑似限流”，从请求后第 60 秒开始冷却 900 秒。期间仍观察新状态，有有效快照就转为处理；不换号或持续请求。
   冷却到期才关闭仍打开的拍卖行（一次 Escape；输入框打开则停止），重开拍卖行，显式 `/as scan` 一次并确认新 runID。已经关闭的拍卖行不再盲按 Escape。默认最多重试两次；配置可设为 0 禁用重试。`scanTimeoutSeconds` 仅限制已收到快照后的处理时间，不把正常处理慢误判为限流。
7. 本轮扫描完成、核心记录和链接完整、市场范围无未知后才输入 `/logout`。提交小退前再次检查本轮编号与完整性状态。
8. 确认返回选角页、角色级 SavedVariables 出现新写入且稳定，再流式解析全部文件。核对角色、服务器、角色 GUID、本轮 runID、时间、实际记录条数和市场范围缺失计数，复制验证后归档；之后才能处理下一角色。

最后一个成功角色停在选角页，不退出客户端、不清空源数据。启用同步时，后台队列可继续完成网站上传。身份变化、读取失败、扫描错误等异常进入上述恢复流程；保留已完成归档。用户主动停止不会强制结束游戏。

## 输入与状态边界

- 输入使用目标 HWND 的 PostMessage，不使用全局剪贴板、SetForegroundWindow 或 SendInput。
- 不自动恢复最小化窗口；恢复最小化窗口的实测未能保持前台焦点。应使用普通后台窗口，最小化状态下的帧更新/心跳不能视为已验收。
- Enter 打开聊天框后，先从插件确认空聊天输入框，再发送固定允许列表里的 Unicode 文本；读回完全匹配的命令标记后才提交。插件只输出匹配标记，不输出用户聊天内容。
- 窗口归属变化、按住修饰键、角色身份变化、战斗、心跳停止、错误/缺失记录都会中止。中途停止可能保留尚未提交的聊天输入框，不盲发 Escape 或 Enter。
- 状态桥只读取插件的小型状态字符串；完整拍卖数据使用正常小退写文件。指针定位后校验帧、心跳、会话；不会保存无关内存。
- 原生选角偏移只支持已核实的 `12.1.5.70575` SHA-256。错误弹窗、分组导航、账号切换等场景尚未全面验收；不能将原型称为任意版本的无人值守服务。
- 启动成功不等于登录成功。凭据失效时等待角色页超时并停止；不会恢复独立世界协议或新增凭据续期逻辑。

## 验证

`go test ./cmd/state-probe ./internal/snapshot` 和 `go vet ./cmd/state-probe`。

测试包含：Lua 插件加载与状态帧校验、关闭自动模式撤销小退标记、重复/关闭拍卖行事件不重复请求、错误运行编号与缺失市场范围拒绝完成、状态帧损坏/重复字段拒绝解析、归档身份字段和重复字段检查。异常恢复测试覆盖进程重置调用、重启后保留冷却、原轮次与调度时间、以归档校验重建进度以及拒绝损坏/旧轮次/错误角色归档。强杀和恢复尚未在真实采集中实测。

冷却测试使用模拟时间覆盖 59/60/959/960 秒边界、拍卖行已关闭不提前重试、迟到数据取消重试、慢扫描不进入冷却、重试上限、新请求重新计时以及无效时间戳。插件指针切换竞态会丢弃本次读取并在心跳时限内重读；旧会话和停止的心跳仍拒绝。

启动前插件修复的测试还检查：仅改指定插件、保留其他插件设置及换行、保留修改前备份、重复执行不再次修改。2026-10-30 实机已验证正常关闭、启用熊猫酒仙角色的插件、直接启动客户端、定位并发送进入世界按键；后续结果见本机运行目录的 `events.jsonl`。
