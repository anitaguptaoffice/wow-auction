# AuctionSearchExample

2.9.0 开发版按当前采集流程默认开启自动采集：打开拍卖行后，本次角色登录最多自动请求一次。`/as auto off` 可关闭，改用按钮或 `/as scan` 手动请求。插件通过 `C_AuctionHouse.ReplicateItems()` 请求拍卖快照：

- 请求阶段：等待服务器返回快照；无响应可能与限流有关，不据此推断精确限流范围，不自动重试
- 超过 60 秒无响应：显示 `AS_RATE_WAIT`（疑似限流）。插件自身不循环发请求；Go 控制器可按“60 秒无响应后冷却 15 分钟，默认最多两次”的策略重开拍卖行并显式重试。正常数据处理不触发该策略。
- 扫描阶段：显示已处理数量、总数、百分比和进度条
- 完成阶段：显示实际保存条数、耗时及包含 `itemLink` 的条数；核心字段有缺失时会显示橙色警告

进入角色后先显示 `AS_READY`；请求发出后进入 `AS_WAITING`。自动模式下，完整性检查通过后显示 `AS_LOGOUT_READY`，由 Go 控制器执行正常小退并验证归档；插件自身不调用受保护的退出函数。`StatusBridge.lua` 发布小型状态心跳供电脑端确认身份、扫描编号及进度，`Preparation.lua` 仅观察坐骑、目标、施法和固定命令匹配状态，不发布聊天正文。统一入口见 [后台采集说明](../../../automation/wow-runner/BACKGROUND_COLLECTION.md)。

正常扫描不会向聊天框输出批次日志。调试命令：

- `/as stats`：查看已保存扫描统计
- `/as scan`：拍卖行打开时手动开始一次全量扫描
- `/as export`：序列化当前快照，通过只读内存通道导出；面板也有「导出到电脑」按钮
- `/as stop`：停止导出
- `/as resend all` 或 `/as resend 18,93`：重新发布全部或指定数据块，让接收器补齐漏块
- `/as history <物品ID>`：查看指定物品的最近记录
- `/as test [物品ID]`：检查客户端物品缓存
- `/as uitest scanning`：预览进度面板（也可传入 `started`、`complete`、`warning` 或 `error`）
- `/as clear`：清空插件保存的数据

传统 SavedVariables 路径需要小退、退出游戏或 `/reload` 才会写入磁盘上的 `AuctionSearchExample.lua`。2.8.0 改用只读内存导出，无需为每次导出小退，不再加载 TTS 代码。首次更新仍须重启或加载插件。使用前启动电脑接收器，详见 [内存导出说明](../../memory-bridge/README.md)。

导出分为序列化和逐块发布两个阶段，不压缩、不转 Base64。256 KiB 原始块每 50 毫秒发布一次，自动重复 3 轮。游戏显示发布进度；电脑端进度页显示已校验接收的真实进度。只有电脑端“校验通过、已保存”才代表传输完成。缺块可手动重新发布，扫描缺失计数仍由原有入库校验器验证。原始块保留用于补发；新扫描或 `/as clear` 时释放。
SavedVariables 使用角色级存储，并且每个角色只保留最新一次成功快照，不在游戏内加载和维护历史记录。服务器返回新快照后会释放该角色上一份，成功后用本次结果替换；其他角色的文件互相隔离。历史追加与长期保存由游戏外的同步程序或数据库负责。这样既保持现有导入格式兼容，也避免登录一个角色时加载其他角色的数百 MB 快照。

每次扫描还会记录当前 `region`、`realm`，并按唯一 `ItemID` 保存一次市场范围：

- `region`：区域共享商品（Commodity）；
- `realm`：当前服务器/连接区独有物品；
- `unknown`：客户端暂未返回商品状态，网站会显示“范围待确认”。

市场范围使用 `ITEM_KEY_ITEM_INFO_RECEIVED` 事件异步补全。插件最多同时等待 32 个唯一物品的结果，每帧也限制启动数量，并设置 180 秒总超时；范围查询失败只会保留为 `unknown`，不会丢失或破坏已经采集完成的核心拍卖记录。

插件面向 WoW 12.1，TOC 接口版本为 `120100`。
